# OpenClash 订阅转换模板（Aethersailor Full · 58 组）

给 [subconverter](https://github.com/tindy2013/subconverter) 用的**外部配置模板**（对应转换接口的 `config=` 参数），供 OpenClash 做订阅转换时调用。

它只定义**策略组**和**分流规则**，不含节点、订阅地址、token 或任何个人信息，因此可以公开托管，给**任意机场的任意订阅**复用。

**两份文件，都在 `main` 分支同一目录，按需选一个**（只差 6 行 URL，其余完全一样）：

| 版本 | 地址 | 一句话 |
|---|---|---|
| 跟随上游（推荐，日常用） | `https://cdn.jsdelivr.net/gh/cartoonsh/openclash-ini-template@heads/main/openclash-aethersailor-full.ini` | 规则跟着上游自动更新，省心 |
| 规则锁定版 | `https://cdn.jsdelivr.net/gh/cartoonsh/openclash-ini-template@heads/main/openclash-aethersailor-full-pinned.ini` | 规则内容永不变化，可预期、可复现 |

拿不定就用第一个。两份文件的业务差异只有 6 行规则集 URL（另有 7 行注释说明），其余逐字相同。详细区别见 [§十一](#十一两份文件跟随上游-还是-锁定规则)。

---

## 一、30 秒用法

1. 复制上面那行 jsDelivr 地址
2. OpenClash → 配置订阅 → 编辑（或新增）订阅
3. 「订阅转换」开关保持开启
4. 「模板名称」下拉里选 **自定义**（Custom Template）
5. 下面会多出一栏「自定义模板地址」，把地址粘进去
6. 保存 → 应用 → 更新订阅

之后每次订阅更新（你设 3 小时一次也行），转换站都会按这个模板重新生成配置，**不需要手动转换**。

> 只改一条订阅也行，先在一个订阅上试；不放心就留着原来的 ACL4SSR 那条对照。

## 二、这个文件是什么

一句话：**它就是 Aethersailor 官方 `Custom_Clash_Full.ini`，只加了一条过滤规则。**

| 项目 | 值 |
|---|---|
| 上游来源 | [Aethersailor/Custom_OpenClash_Rules](https://github.com/Aethersailor/Custom_OpenClash_Rules) 的 `Custom_Clash_Full.ini` |
| 策略组 | 58 个（官方 63 个，5 个国外 AI 组已并入 `🤖 国外AI服务`） |
| 规则行 | 63 条 `ruleset=`（官方上限 64，留 1 条余量） |
| 转换器输出 | 63 条规则 + 6 个 rule-providers（默认模式） |
| 本文件相对官方 | 只多 1 条 `exclude_remarks`（连同 6 行注释），其余逐字相同 |
| 文件大小 | 32,375 字节（锁定版 33,137 字节） |

### 唯一改动：过滤机场的「伪节点」

机场常把套餐信息塞成节点，名字长这样：

```
剩余流量：942.68 GB
套餐到期：长期有效
到期:2027-09-25;剩余:2998.57 GB
[重要提示]若节点超时，请到网站…
```

这些不是服务器，选中就连不上。它们还会污染 `♻️ 自动选择` 这类 `url-test` 组——测速永远失败，但节点列表里就是有它。

本文件加的一条就是干掉它们：

```ini
exclude_remarks=(^[\[【(（]?(剩余流量|到期|套餐到期|重要提示|距离下次重置|官网[:：]|流量[:：])|剩余[:：][ ]*[0-9.]+)
```

**关键是行首锚定**：只有「整条名字就是一句套餐文案」才删。

这条规则是被真实误杀案例改出来的。最早的写法是裸关键词 `(到期[:：]|剩余|…)`，结果把 Bluetile 一个**能用的真节点** `96613;官网:https://apple.bluetile.wang` 也删了——只因为名字里有「官网:」。类似地，`香港-剩余IP优化`、`新加坡-已用带宽优化`、`有效期节点`、`香港-不过期` 这类正常名字都会被误删，而且**没有任何日志**，用户只会觉得"机场少给了我节点"。

所以现在的取舍是：**宁可漏杀，不可错杀**。

- 会被删：`剩余流量：…`、`套餐到期：…`、`到期:2027-…`、`[重要提示]…`、`官网:…`、`剩余:100G`
- 会被放行：`96613;官网:…`、`香港-剩余IP优化`、`日本-大流量专线`、`有效期节点`
- **已知漏网**：以 emoji 开头的 `🕖到期时间: …`、`⏳剩余流量: …` 不会被删，会落进 `🌐 其他地区`。它们测速本就失败，url-test 不会选它们，无害。

官方模板没有这一步。

### 为什么不自建分组（踩过的坑）

我第一版是自己拼的 59 组，结果**漏了 4 个组**：`🇨🇦 加拿大节点`、`🇹🇷 土耳其节点`、`🏠 家宽节点`、`🐢 低倍率节点`。

问题在于 `🌐 其他地区` 的正则里带了排除项：

```
^(?!.*(港|…|加拿大|…|土耳其|…|家宽|…|低倍率|…)).*
```

也就是说加拿大、土耳其、家宽、低倍率节点**被明确排除出「其他地区」**，等着进它们各自的专属组。我把那 4 个组删了却没改这条正则，结果这些节点既进不了地区组、也进不了「其他地区」——**在分组里彻底消失**。

所以现在直接沿用官方 63 组的结构，不自己造，只把 5 个国外 AI 组（ChatGPT / Copilot / Claude / Gemini / Grok）合并进 `🤖 国外AI服务`，变成 58 组。好处有两个：不会漏组；上游改规则时重新同步一次即可，不会越改越偏。

## 三、包含什么、不包含什么

| 内容 | 是否包含 | 说明 |
|---|---|---|
| 策略组定义（58 组） | 包含 | 组名、类型（`select` / `url-test`）、测速地址与间隔 |
| 节点名匹配正则 | 包含 | 例如 `港\|HK\|Hong Kong`，用于把节点自动归入地区组 |
| 分流规则 | 包含 | 49 条 `GEOSITE` + 7 条 `GEOIP` + 6 个远程规则集 + 1 条 `FINAL` |
| 伪节点过滤 | 包含 | `exclude_remarks`，剔除套餐信息节点 |
| 节点（服务器、端口、密码） | **不包含** | 由转换器在转换时从你填的订阅地址实时注入 |
| 订阅地址 / token | **不包含** | 属于请求参数，不写进模板 |
| DNS 设置 | **不包含** | 由 OpenClash 生成运行配置时注入 |

### 为什么不含节点

不是刻意删的，是**文件类型决定的**。

subconverter 的外部配置（`config=` 指向的 ini）只是「配方」：描述怎么分组、怎么分流。节点是「食材」，转换时从你填在订阅地址里的那条链接实时取。在 ini 里写 `proxies:` 也不生效——它不是一份完整配置。

反过来，这正好是它能公开的原因：**配方里没有任何你的信息**。

### 那为什么「其他文件都含节点」

因为它们分属不同环节，不是同一类东西：

| 文件 | 含节点 | 含分组 / 规则 | 用途 | 能否公开 |
|---|---|---|---|---|
| 本文件（subconverter ini） | 否 | 是 | 转换时的模板 / 配方 | **可以** |
| 完整 Clash YAML | 是（`proxies:`） | 是 | 直接给 mihomo 运行 | 不可以（含节点密码） |
| proxy-provider YAML | 否（远程引用） | 否 | 只提供节点列表 | 视情况 |
| 机场原始订阅 | 是 | 部分 | 待转换的原料 | 不可以（含 token） |

成品和原料必然含节点，模板按机制用不到节点。而本文件里有的是订阅里**没有**的东西——58 组结构、地区匹配正则、63 条分流规则、伪节点过滤，这些跟具体机场无关，换任何订阅都能用。

如果你需要「含节点」的成品，那是完整 Clash YAML，只能本地用，**不能公开**。

## 五、分流规则怎么来

63 条 `ruleset=` 行的构成：

| 类型 | 条数 | 说明 |
|---|---|---|
| `[]GEOSITE` | 49 | 直接引用 mihomo 内置 geosite 分类，如 `telegram`、`netflix`、`category-ai-!cn` |
| `[]GEOIP` | 7 | 内置 geoip，含 `private`、`cn` 兜底 |
| `clash-domain:` 远程规则集 | 2 | `Custom_Direct_Domain.mrs`、`Custom_Proxy_Domain.mrs` |
| `clash-classic:` 远程规则集 | 4 | `Custom_Direct_Classical_IP`、`Custom_Proxy_Classical_IP`、`Steam_CDN_Classical`、`Custom_Port_Direct` |
| `[]FINAL` | 1 | 兜底，指向 `🐟 漏网之鱼` |

转换之后长什么样，**取决于转换器有没有把远程规则集展开**。两种情况我都用真实内核校验过，都能正常加载，模板不用改。

### 情况 A：不展开（OpenClash 的实际行为）

OpenClash 拼转换地址时不带 `expand`，于是远程规则集保留成 `rule-providers`：

| 规则类型 | 条数 |
|---|---|
| GEOSITE | 49 |
| GEOIP | 7 |
| RULE-SET（指向 6 个远程规则集） | 6 |
| MATCH | 1 |
| **合计** | **63** |

此时输出里有 `rule-providers:` 段，mihomo 按 `interval` 自行更新那 6 个文件（1800 / 28800 秒），不占用规则行数。

### 情况 B：展开（`expand=true`）—— **不要用**

这里有个坑，必须说清楚：**subconverter 不解析 `.mrs` 二进制**。展开模式下，两个 `clash-domain:` 的 `.mrs` 规则集**一条规则都产不出来**，等于 1293 条自定义直连域名 + 17 条代理域名**静默消失**。

剩下的 4 个 `clash-classic` 集（yaml 文本）才能展开，所以总数是 99 条而不是 1293+：

| 规则类型 | 条数 |
|---|---|
| GEOSITE | 49 |
| GEOIP | 7 |
| IP-CIDR | 34 |
| DST-PORT | 4 |
| SRC-PORT | 1 |
| DOMAIN-SUFFIX | 3 |

（这 99 条里，`DOMAIN-SUFFIX` 只有 Steam 的 3 条——正好证明 1293 条自定义域名没进来。）

**结论：`expand=true` 会把规则搞残，而且不报错。** OpenClash 默认不带这个参数，别手动加；也别在 OpenClash 里勾选会触发展开的选项。

那 34 条 `IP-CIDR` / 3 条 `DOMAIN-SUFFIX` / 4 条 `DST-PORT` / 1 条 `SRC-PORT` 是那 4 个 yaml 规则集展开出来的，不是手写的。

> 顺带解释我上一版为什么多出 42 条重复规则：我手写了一遍 IP/端口/域名规则，展开时规则集又给出同样内容，99 变 141。现在规则段完全照抄官方。

## 七、地区组会不会空

会，取决于节点名。

**能归类**：节点名带地区词或旗标，例如 `🇭🇰 [IPLC-香港5-VLESS] ✨ 2x`、`🇯🇵日本专线-0.1倍率`。这类订阅的地区组都有内容。

**会空**：节点用纯域名、纯编号命名（`bgpvless-2342ss.834928.xyz`），正则匹配不到任何地区。此时：

- 地区组是空的（组还在，点进去没东西）
- `🚀 手动选择` 和 `♻️ 自动选择` **仍然列出全部节点**，正常能用
- **注意：空组不会让配置加载失败**。这点和"组里连一个候选都没有"不一样——带 `use:` + `filter:` 的组即使过滤结果为 0，mihomo 也照样启动（实测 `-t` successful），只是那个组点进去是空的、规则命中它时连接会失败。它是个**静默黑洞**，不报错。
- 反过来，**如果某个组既没有 `proxies:` 也没有 `use:`，mihomo 会直接拒绝加载**：`proxy group[0]: X: 'use' or 'proxies' missing`。这是硬错误。

模板给「手动选择」留了 `.*` 兜底就是为这种情况。

### 那怎么让某个空组消失？别直接删那行

⚠️ **直接删掉 `custom_proxy_group=🇨🇦 加拿大节点…` 那行会把配置改坏。** 因为另外 **45 个**组的候选列表里都写着 `[]🇨🇦 加拿大节点` 这个引用，删掉定义后 mihomo 报：

```
proxy group[x]: 🚀 手动选择: '🇨🇦 加拿大节点' not found
configuration file test failed
```

配置直接加载不了（实测 v1.19.34）。

正确做法二选一：

- **A（推荐）**：不动模板，接受那个组是空的。它不影响使用。
- **B**：先改 `🌐 其他地区` 的排除正则，把该地区词从排除项里拿掉（让节点落进「其他地区」），**再**删组定义，**并且**把其余 45 个组里的 `[]该组名` 引用全部删掉。三件事都做，缺一就坏。

## 八、已知限制

1. **必须用支持 `config=` 参数的转换后端。** OpenClash 默认的 `api.asailor.org`、`api.wcc.best` 都支持；自建 subconverter 也支持。有些只支持 `template=` 的后端不行。
2. **转换站要能拉到 jsDelivr。** 规则集和本模板都走 jsDelivr，所以两个都得通。实测 `raw.githubusercontent.com` 在部分转换站会拉到空内容或旧内容，**不建议换成 raw 地址**。
3. **仓库必须公开**，因为拉取模板的是境外转换站。
4. **63 条 ruleset 逼近某些后端 64 条上限。** 官方注明兼容 `max_allowed_rulesets=64`，本模板留了 1 条余量，别再加远程规则集。
5. **需要 mihomo（Meta）内核**，因为用了 `GEOSITE` / `GEOIP`。原版 Clash 内核跑不了。
6. **节点是内联还是 `proxy-providers`，模板控制不了。** 这是转换器行为：本模板 + 这 10 个订阅，输出都是 `proxy-providers`，节点由 mihomo 运行时拉取。
7. **伪节点过滤只覆盖中文套餐文案，且只认名字开头。** 英文伪节点（`Traffic: 100G`）、emoji 开头的（`🕖到期时间:`）、机场自定义落地页（`[50万资源服] ✨ https://…`）都会漏过去，落进 `🌐 其他地区`。这是刻意的取舍：宁可漏杀，不可错杀真节点。
8. **机场侧入口挂了，换任何模板都救不了。** 例如某个订阅的全部节点都指向同一个不可达入口时，模板层面无解。
9. **`clash_meta -t` 不能证明规则集能拉到。** 实测 `-t` 根本不下载 `rule-providers`，URL 写错、jsDelivr 挂了，`-t` 照样绿。真正的验证是看运行后日志里有没有 `[Provider] … pull error`。
10. **`rule-providers` 的缓存目录可能不存在。** 转换产物的路径是 `./providers/…`（相对 `-d /etc/openclash`）。本机实测 `/etc/openclash/providers` 目录当时并不存在——若 mihomo 不会自动创建，6 个规则集写入会失败。上线前建议先确认该目录存在。

## 九、跟随上游更新 / 自己改

**跟上游**：上游是 Aethersailor 的 `Custom_Clash_Full.ini`。它更新后，下载新文件，在 `[custom]` 段后面加回那一行 `exclude_remarks`，覆盖本文件即可。改动只有这一处，很好对齐。

**自己改**：直接编辑 `openclash-aethersailor-full.ini` 并提交，地址不变，OpenClash 下次更新订阅时自动生效（jsDelivr 有几十分钟缓存，急用可换 `fastly.jsdelivr.net`）。

改的时候注意两点：

- `enable_rule_generator=true` 必须保留（删了会得到 `rules: ~`，规则全空）
- 改 `ruleset=` 的**先后顺序**会改变分流结果（自上而下、先命中先赢），但 `ruleset=` 与 `custom_proxy_group=` 谁在前**无所谓**——转换器对这两个键是分别收集的。（早期我以为是顺序敏感，实际不是；真正导致规则变空的是上一行那个开关。）

删地区组的注意事项见第七节，别直接删。

**分支说明**：模板里保留了上游注释掉的「旧版去重配置」写法，方便回退。默认用的是「显示订阅 Provider 中的全部有效节点」那版。

## 十一、两份文件：跟随上游 还是 锁定规则

### 这 6 个远程规则集是什么

模板里有 6 条规则不是内联的，而是引用 Aethersailor 仓库的规则文件：

| 文件 | 内容 | 刷新间隔 |
|---|---|---|
| `Custom_Direct_Domain.mrs` | 直连域名 1293 条 | 1800 秒 |
| `Custom_Direct_Classical_IP.yaml` | 直连 IP 12 条 | 28800 秒 |
| `Custom_Proxy_Domain.mrs` | 代理域名 17 条 | 28800 秒 |
| `Custom_Proxy_Classical_IP.yaml` | 代理 IP 1 条 | 28800 秒 |
| `Steam_CDN_Classical.yaml` | Steam 下载 CDN 26 条 | 28800 秒 |
| `Custom_Port_Direct.yaml` | 80/443 之外的端口 3 条 | 28800 秒 |

关键点：**默认模式下它们是 mihomo 在路由器上运行时自己拉的**，不是转换器下载进配置里。所以：

- 不管你更新不更新订阅，它们都会按 `interval` 自己刷
- 拉取失败不会让服务挂掉：日志里刷 `[Provider] … pull error`，有缓存时继续用上一次的文件，没缓存则该规则集为空
- 实测路由器直连 jsDelivr：HTTP 200，0.95 秒

### openclash-aethersailor-full.ini：跟着上游走（默认推荐）

- 优点：上游是活跃项目（每天自动生成派生规则文件），站点换 CDN、新增 IP 段这类修正你立刻拿到。
- 风险：上游把某个文件改坏，你跟着中招，而且**没有回滚手段**。

### openclash-aethersailor-full-pinned.ini：锁定规则

同一目录下的独立文件，不靠分支。它与上面的主文件**只差 6 行 URL**：把 `@main` 换成具体提交号 `@b64d5ac1828495be49751d123daeffff36df1e51`（2026-11-22）。jsDelivr 对 commit 是**不可变缓存**，内容永远停在那一刻。

- 优点：行为可预期、可复现，不受上游改动影响。
- 代价：上游的修复也拿不到。要刷新时，把 6 行里的 sha 换成上游 main 的最新提交即可（跟我说一句就行）。

> 早期这第二份是放在 `frozen-rules` 分支上的，现已删除，改成同目录独立文件：换模板地址时不用切分支，两份文件用同一条 `@main` 路径取，缓存行为一致。

### 为什么不做「把规则文件搬进本仓库」

效果和 pinned 版完全一样（内容都不再变），却要多维护 6 个文件，还得处理 `.mrs` 是二进制、没法用网页编辑器上传的问题——收益为零。所以「锁定」用固定 commit 实现，不搬文件。

真要「一个外部文件都不吃」，唯一有意义的做法是**删掉这 6 条远程规则**，只留 49 条 GEOSITE + 7 条 GEOIP + 兜底。代价：

- `🔀 非标端口` 组失效（没有规则再引用它）
- Steam 下载不再走直连 CDN，改走代理
- 自定义直连域名 / IP 名单丢失，部分国内站点可能被代理

不建议，也没做成单独文件。真需要随时可以做。

## 十二、第三方审核记录

这份文档和模板在发布后做了两轮独立审核（一个事实核对、一个红队找故障），改出了 5 处真实问题。列在这里，方便你判断哪些结论可信、哪些是我自己拍的。

| # | 原来的说法 / 做法 | 实际情况 | 现在的处理 |
|---|---|---|---|
| 1 | `exclude_remarks` 用裸关键词 `剩余\|官网[:：]\|…` | **会误杀真节点**：`96613;官网:https://…` 被删，且无日志 | 改成行首锚定，误杀消失，漏杀 2 类 emoji 伪节点 |
| 2 | 第七节「不想看到空组就删掉那行」 | **删了直接加载失败**：`'X' not found`，另有 45 个组引用它 | 改成「接受空组」或「三件事一起做」 |
| 3 | 第五节「expand 模式也是 99 条，两种都行」 | **expand 会丢掉 1293 条自定义域名**（转换器不解析 `.mrs`），且不报错 | 改为明确警告「不要用 expand」 |
| 4 | 第四节 25 个组名写错（缺"节点"、缺 emoji、`Disney+`≠`DisneyPlus`） | 面板里搜不到对应组 | 全部换成与模板逐字一致的名字 |
| 5 | 第九节「ruleset 必须写在 custom_proxy_group 之前」 | 伪约束，转换器对两个键分别收集 | 已更正，真正相关的是 `enable_rule_generator` |

同时补上两条之前没说清的限制：`-t` 不校验规则集可达性（第八节第 9 条）、空 `filter` 组是静默黑洞（第七节）。

**审核也替我确认了这些是对的**（实测，不是推测）：

- 规则段（63 条 `ruleset=`）与官方模板逐字节一致；策略组在官方 63 组基础上合并了 5 个国外 AI 组，现为 58 组；另有 `exclude_remarks` 与注释差异
- 6 个 `@sha` 锁定地址全部可用，jsDelivr 对 commit 不可变缓存成立
- 63 条规则 + 6 个 rule-providers 的结构能被 mihomo 正常加载
- 文档里引用的报错文本 `proxy group[0]: … 'use' or 'proxies' missing` 一字不差
